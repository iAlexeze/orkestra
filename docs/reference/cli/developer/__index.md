# Developer CLI

The developer CLI is the fastest path from a local project to a running, production-grade
deployment on Kubernetes — without writing operator code, managing Helm charts, or configuring
monitoring pipelines by hand.

Three commands cover the entire lifecycle:

| Command | What it does |
|---------|-------------|
| [`ork doktor`](./doktor.md) | Examine the project, show what Orkestra detected, and generate the `.orkestra/` configuration |
| [`ork deploy`](./deploy.md) | Build the Docker image, push it, generate the cluster bundle, install Orkestra, and roll out |
| [`ork deploy rollback`](./rollback.md) | Instantly restore the previous image — no rebuild required |

---

## The workflow

```
your project directory
        │
        ▼
ork doktor                          ← understand what Orkestra sees
ork doktor init --name my-app       ← generate .orkestra/ config
        │
        ▼
ork deploy --registry ghcr.io/org   ← build → push → deploy → watch
        │
        ├─ deploy succeeds ──────────────────────────► done
        │
        └─ replicas not ready ──► ork deploy rollback ← instant restore
```

---

## What you get out of the box

Every deployment generated by `ork doktor init` includes:

- **Deployment** with rolling updates and a configurable replica count
- **Service** exposing the container port
- **HPA** scaling 2 → 10 replicas on CPU (disable with `--no-ha`)
- **PDB** keeping at least one replica available during disruption
- **Deletion protection** labels that block accidental `kubectl delete`
- **Declarative status** — `status.phase` tracks `Pending → Deploying → Ready`
- **Developer notifications** — when replicas stall in `Deploying`, Orkestra sends
  you logs commands and a rollback hint (wire with `--notify-me`)

## Prerequisites

| Tool | Purpose | Auto-installed? |
|------|---------|-----------------|
| Docker | Image build and push | No — install manually |
| kubectl | Apply manifests, watch rollout | Yes — `ork deploy` installs if missing |
| helm | Install the Orkestra operator | Yes — `ork deploy` installs if missing |
| A container registry | Store images | Required — pass via `--registry` |

For local development without a registry, use `--dev` to spin up a
[kind](https://kind.sigs.k8s.io) cluster with a local registry.

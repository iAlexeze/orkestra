# ork generate runtime

`ork generate runtime` produces the Go code that connects typed API types, hooks, and custom constructors to the Orkestra runtime. It reads the Katalog and emits `zz_generated_runtime_registry.go` in the output directory.

This command is only needed for typed-mode CRDs — CRDs with `apiTypes.location` set, or CRDs with Go hooks or constructors. Dynamic-mode CRDs with only declarative templates do not need code generation.

---

## When you need it

| Situation | Needs `ork generate`? |
|---|---|
| Dynamic CRD, declarative templates only | No |
| Dynamic CRD with dynamic hooks (unstructured) | No |
| Typed CRD with `apiTypes.location` | Yes |
| Typed hooks using concrete Go structs (`obj.Spec.Image`) | Yes |
| Custom constructor | Yes |

If you run `ork run` with a typed-mode CRD and the generated file is missing or stale, startup fails with:

```
error: no object factory for demo.orkestra.io/v1alpha1, Kind=Website
  — run: ork generate runtime --katalog katalog.yaml
```

---

## What it generates

`zz_generated_runtime_registry.go` contains one `init()` function that populates the package-level registries:

```go
// zz_generated_runtime_registry.go
// Code generated by ork generate runtime. DO NOT EDIT.

package main

import (
    apiv1   "github.com/myorg/api/website/v1alpha1"
    hooks   "github.com/myorg/hooks"
    "k8s.io/apimachinery/pkg/runtime/schema"
)

func init() {
    // ── Object registry ────────────────────────────────────────────────────
    // Factory functions for typed runtime objects, keyed by GVK.
    // Used by konstructOrkestra to set CRDEntry.DynamicModeObject.
    orktypes.ObjectRegistry[schema.GroupVersionKind{
        Group:   "demo.orkestra.io",
        Version: "v1alpha1",
        Kind:    "Website",
    }] = func() runtime.Object { return &apiv1.Website{} }

    orktypes.ListRegistry[schema.GroupVersionKind{
        Group:   "demo.orkestra.io",
        Version: "v1alpha1",
        Kind:    "Website",
    }] = func() runtime.Object { return &apiv1.WebsiteList{} }

    // ── Scheme registration ────────────────────────────────────────────────
    // Adds Go types to the scheme so the REST client can decode responses.
    orktypes.SchemeRegistry = append(orktypes.SchemeRegistry, apiv1.AddToScheme)

    // ── Hook registry ──────────────────────────────────────────────────────
    // Maps GVK to hook factory functions declared in reconciler.hooks.
    orktypes.HookRegistry[schema.GroupVersionKind{
        Group:   "demo.orkestra.io",
        Version: "v1alpha1",
        Kind:    "Website",
    }] = hooks.WebsiteHooks

    // ── Reconciler registry ────────────────────────────────────────────────
    // Maps GVK to constructor functions declared in reconciler.constructor.
    // Only present when reconciler.default: false.
    // orktypes.ReconcilerRegistry[...] = reconcilers.NewDatabaseReconciler
}
```

## Usage

```bash
ork generate runtime --katalog katalog.yaml

# Options
ork generate runtime \
  --katalog komposer.yaml \    # Katalog or Komposer
  --output  ./cmd/ork/         # directory to write the file
  --package main               # package name in the generated file
```

**Default output:** the directory containing the Katalog file.
**Default package:** `main` (matches `cmd/ork/`).

The generated file always starts with `zz_` so editors and `go vet` treat it as generated code. It is committed to version control — the `init()` function must be present when the binary is built.

---

## Re-running after changes

Re-run `ork generate runtime` whenever you:

- Add a new typed-mode CRD to the Katalog
- Change `apiTypes.group`, `apiTypes.version`, or `apiTypes.kind` for a typed CRD
- Add or change a `hooks.function` declaration
- Add or change a `constructor.function` declaration
- Change the `location` of a hook or constructor module

The generated file is idempotent — running it multiple times produces the same output.

!!! tip "Add to your Makefile"
    ```makefile
    generate:
        go run ./cmd/ork/main.go generate runtime --katalog katalog.yaml
        go build ./...
    ```
    Run `make generate` before `go build` whenever the Katalog changes.

---

## How it reads the Katalog

`ork generate runtime` runs the same Katalog loading path as `ork run` — it calls `KomposeKatalogFromYaml`, which enriches all CRD entries, and then reads the result to produce the registry entries.

This means if your Katalog has a syntax error or references an unknown kind, `ork generate runtime` will fail with the same error as `ork run`. Fix the Katalog error first, then re-run generation.

---

## Dynamic hooks do not need generation

If you write hooks that operate on `*unstructured.Unstructured`, you can wire them directly without code generation:

```go
// In your main.go or konstructOrkestra equivalent:
orktypes.HookRegistry[gvk] = hooks.MyDynamicHooks
```

Code generation is only needed when the Katalog YAML declares `hooks.location` and `hooks.function` — those fields are the signal that `ork generate` needs to emit a registry entry for that GVK.

## Troubleshooting

**`no object factory for ...`**

The GVK in the error is not in `ObjectRegistry`. Either:
- `ork generate runtime` has not been run after adding this CRD
- The Katalog's `apiTypes` fields changed since the last generation
- The generated file is not included in the build

**`no hook factory for ...` (warning, not fatal)**

A `hooks.function` is declared in the Katalog but the GVK is not in `HookRegistry`. Check that `ork generate runtime` was run and the output file is in the correct package.

**`AddToScheme not found`**

The `apiTypes.location` path does not export an `AddToScheme` function. This function is generated by `controller-gen`. Run `controller-gen object:headerFile=... rbac:... crd:... output:...` against your API types package first.

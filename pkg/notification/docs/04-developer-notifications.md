# 04 — Out-of-the-box Developer Notifications

## What this is

Every Katalog generated by `ork doctor init` ships with a `notify:` block on the
deployment readiness condition. The moment a deploy stays in the `Deploying` phase
longer than the notification interval (default 15 minutes), Orkestra alerts the
`developer` team directly — with the exact command to check logs and a one-liner
to roll back.

No custom alerting rules. No Prometheus. No PagerDuty. The observability that
usually requires a separate platform is built into the deployment definition.

---

## The condition wired into every katalog

```yaml
operatorBox:
  status:
    fields:
      - path: phase
        value: "Deploying"
        when:
          - field: data.image
            exists: true
          - field: "{{ replicasReady .children.deployment }}"
            equals: "false"
            notify:
              teams: [developer]
              message: >
                {{ .metadata.name }} is deploying but replicas are not ready yet.
                Check logs: kubectl logs -n {{ .metadata.namespace }} -l ork.io/app={{ .metadata.name }} --tail=50
                | Roll back if stuck: ork deploy rollback
```

The `replicasReady .children.deployment` check evaluates to `"false"` whenever the
deployment's ready replica count is below the desired count. The `notify:` block fires
when that condition is true and the interval gate has not been tripped.

**The `developer` team is a no-op if no team is configured.** The `notify:` is always
present in the generated Katalog. If `notification.teams.developer` does not exist, the
reference is silently skipped — the Katalog is valid whether or not `--notify-me` was
used.

---

## Wiring the developer team

Run `ork doctor init` with `--notify-me` to configure the `developer` team automatically:

```
ork doctor init --name my-app --notify-me
```

Orkestra reads your Git author email and SMTP/Slack vars from `.env` to build the team:

```yaml
notification:
  enabled: true
  defaults:
    interval: 15m
    # slackWebhookUrl injected via SLACK_WEBHOOK_URL in orkestra-notification Secret
  teams:
    developer:
      email:
        - alex@example.com       # from git log -1 --pretty=format:%ae
      slack:
        - "#deployments"         # present when SLACK_WEBHOOK_URL is in .env
      message: "{{ .metadata.name }}: {{ .status.phase }}"
```

SMTP and Slack credentials are never baked into the Katalog. They live in the
`orkestra-notification` Secret in `orkestra-system`, injected into the Orkestra runtime
via `runtime.extraEnvFrom` so `pkg/konfig` picks them up as normal env vars:

```
SMTP_HOST / SMTP_PORT / SMTP_USER / SMTP_PASS / SMTP_FROM
SLACK_WEBHOOK_URL
```

`ork deploy` creates and applies this Secret automatically when `.env` contains
`SMTP_*` or `SLACK_*` variables.

## What the developer receives

**Email** (when SMTP is configured):

```
From: deploy@mycompany.com
Subject: [orkestra] replicasReady condition triggered
To: alex@example.com

my-api is deploying but replicas are not ready yet.
Check logs: kubectl logs -n my-api-orkestra-ns -l ork.io/app=my-api --tail=50
Roll back if stuck: ork deploy rollback
```

**Slack** (when SLACK_WEBHOOK_URL is configured):

```
my-api is deploying but replicas are not ready yet.
Check logs: kubectl logs -n my-api-orkestra-ns -l ork.io/app=my-api --tail=50
Roll back if stuck: ork deploy rollback

[Katalog: my-api]  [Team: developer]
```

## Interval behaviour

The default interval is 15 minutes (`notification.defaults.interval: 15m`). Orkestra
will not re-send for the same condition+team pair within that window, even if the
condition remains true across multiple reconcile cycles. Override per team:

```yaml
notification:
  teams:
    developer:
      interval: 5m   # check in more frequently for this team
```

On Orkestra restart, the in-process interval clock resets. The next true evaluation
after restart will always deliver — treat restarts as a "clock cleared" event.

## Extending notifications to other conditions

The same `notify:` block works on any `when:` condition in the Katalog — not just
deployment readiness. Add it wherever you want the developer team to be alerted:

```yaml
# Notify when the app hits an error phase
- path: phase
  value: "Error"
  when:
    - field: "{{ replicasReady .children.deployment }}"
      equals: "false"
      notify:
        teams: [developer]
        message: "{{ .metadata.name }} entered error state — investigate immediately."

# Notify on custom metric threshold (requires metrics provider)
- field: metrics.errorRatePercent
  greaterThan: "5"
  notify:
    teams: [developer]
    message: "{{ .metadata.name }}: error rate {{ metrics.errorRatePercent }}% exceeded threshold."
```
